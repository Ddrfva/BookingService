# 🏨 BookingService

## 📋 Описание

Pet-проект: Web API для управления бронированиями комнат.
Есть функционал администратора (управление комнатами) и пользователя
(создание и просмотр броней). Написан на C# в учебных целях.

## ✨ Функционал

**Администратор:**
- создать комнату (класс, стоимость, описание)
- получить комнату по id и списком
- удалить комнату — нельзя удалить, если на неё есть брони (409)

**Пользователь:**
- забронировать комнату на свободные даты
- получить информацию о бронировании по id
- нельзя забронировать комнату на даты, которые уже заняты другой
  бронью (409)

## 🛠 Стек

- .NET 8, ASP.NET Core Web API
- Entity Framework Core 8 (Code First, миграции)
- PostgreSQL 16 в Docker (docker-compose)
- Swagger — документация и ручная проверка API

## 🗂 Структура проекта (слои)

```
BookingService
├── docker-compose.yml
└── BookingService
    ├── Controllers/    # HTTP-слой: принять запрос, вызвать сервис, вернуть ответ
    ├── Application/    # Dtos (запросы/ответы) + Services (бизнес-логика)
    ├── Domain/         # сущности Room, Booking и enum RoomClass
    ├── Data/           # AppDbContext
    └── Migrations/     # миграции EF Core
```

Зависимости направлены внутрь: Controllers → Application → Domain,
Data → Domain. Domain ни от чего не зависит.

## 🚀 Запуск

Понадобятся: .NET 8 SDK, Docker Desktop, Visual Studio (или Rider).

1. Поднять базу (из папки с `docker-compose.yml`):

   ```bash
   docker compose up -d
   ```

2. Применить миграции (консоль диспетчера пакетов):

   ```
   Update-Database
   ```

3. Запустить проект, открыть Swagger: `https://localhost:7081/swagger`

База в контейнере слушает порт 5433, чтобы не конфликтовать
с локальным PostgreSQL. Строка подключения — в `appsettings.json`.

## 🔌 API

| Метод | Маршрут | Описание |
|---|---|---|
| POST | `/api/admin/rooms` | создать комнату |
| GET | `/api/rooms` | список комнат |
| GET | `/api/rooms/{id}` | комната по id |
| DELETE | `/api/admin/rooms/{id}` | удалить комнату |
| POST | `/api/bookings` | создать бронь |
| GET | `/api/bookings/{id}` | бронь по id |

Пример создания брони:

```http
POST /api/bookings
Content-Type: application/json

{
  "roomId": 1,
  "userId": 1,
  "startDate": "2026-12-01",
  "endDate": "2026-12-05"
}
```

- `201` — бронь создана
- `400` — дата выезда не позже даты заезда (или другие невалидные данные)
- `404` — комната не найдена
- `409` — комната занята на эти даты

Проверка пересечения дат: брони конфликтуют, если
`новая.Start < существующая.End И новая.End > существующая.Start`.

## ✅ Валидация

Атрибуты DataAnnotations на DTO: цена больше 0, класс комнаты — только
из значений enum, положительные `roomId`/`userId`, непустое описание.
Ошибки валидации возвращаются с кодом 400 в формате ProblemDetails.

## ⚠️ Допущения

- Даты без времени (`DateOnly`); день выезда одной брони может быть
  днём заезда другой.
- Пользователь — это `userId` в запросе, отдельной таблицы и
  регистрации нет.
- Роли разделены только маршрутами (`api/admin/...`), настоящей
  авторизации пока нет.
- Пароль базы учебный, лежит в репозитории.
